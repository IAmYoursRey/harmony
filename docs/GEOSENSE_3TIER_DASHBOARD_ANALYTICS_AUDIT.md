# GeoSense 3-Tier Dashboard & Analytics Integration Audit

## 1. Existing Architecture & Findings

### User Provisioning (Dev Dashboard)
*   **Current Flaw**: Dev dashboard uses `registerAccount` which calls `/api/auth/register`. This API returns an auth token, and the frontend automatically calls `saveToken()`, which logs the Dev out and replaces their session with the newly created Teacher or Student session.
*   **API Flaw**: There is no dedicated `/api/users` endpoint for administrators to create, update, or disable users securely.
*   **Role Representation**: Roles are loosely defined. In the database, they are `dev` and `student`. The application expects `dev`, `teacher`, and `student`.

### Data Ownership (Teacher Dashboard)
*   Teachers currently see students that match their schoolId and class by filtering through `getAllProfiles()`. But the `getAllProfiles()` (`/api/profile/all`) route retrieves **ALL profiles in the entire system**, and `getAllAccounts()` retrieves **ALL accounts**.
*   **Security Risk**: Any logged-in user can intercept the `/api/profile/accounts` or `/api/profile/all` endpoint and download the entire school system's PII.
*   **Missing Isolation**: Backend does not isolate `GET /api/profile` queries by role.

### Analytics Pipeline
*   Currently, the Teacher dashboard calculates analytics on the frontend by aggregating `topicScores` from profiles, which is a legacy system metric. 
*   It does NOT read from `dtResults` (Digital Twin Results), where actual simulation completions are submitted via `/api/digital-twin/rooms/:roomId/result`.
*   There are no dedicated Server Analytics APIs (e.g. `/api/analytics`) to aggregate metrics safely on the backend.

### Performance & React UX
*   **Browser Error**: `Uncaught TypeError: Cannot read properties of undefined (reading 'startTime') at reportAllChanges` stems from the web-vitals package or React Performance observers receiving incomplete navigation entries.
*   **Loading UX**: Fetching data triggers full component re-renders or unmounts, disrupting UX.

## 2. Target Role Model
*   `dev`: Full access to tenant (schools), creates teachers, views system-wide analytics.
*   `teacher`: Isolated to their own `schoolId`. Can manage `classes`, create `rooms` and `simulations`, view `dtResults` generated by their students.
*   `student`: Isolated to their own `schoolId` and `targetClass`. Plays simulations, cannot see other students' results.

## 3. Action Items
*   Create a true `/api/users` backend route protected by `requireDev` and `requireTeacher`.
*   Create an `/api/analytics` backend route to calculate aggregates off `dtResults`.
*   Update `DevDashboardView` and `TeacherDashboardView` to use these new secure APIs instead of downloading the whole DB.
*   Fix the web-vitals React bug.
